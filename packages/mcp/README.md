# @mikeargento/bitgraph-mcp

MCP server for BitGraph. It gives any MCP client, Claude Code and Claude Desktop among them, the gestures the website's drop box has: make a BitGraph, check whether bytes are on record, fetch a proof, and open a position before a task so the task is done inside a BitGraph. The same server is hosted at `https://bitgraph.ing/mcp` for clients that connect by URL; this package runs it locally, reading files on your machine.

Making a BitGraph is one call for any number of files or folders, and everything in the call becomes ONE BitGraph: one Merkle tree under one position (tree/1), every file one leaf; a single file is a tree of one. On your machine each file is read once for its own SHA-256 and a hasher state; an unused position and its floor block are allocated in the ledger before any new file exists; every file's committed bytes, the original plus a registered placement carrying that position's commitment (a 48-byte trailer for formats that ignore trailing bytes, a small tar container with the original first for everything else), are hashed from that state without being written or held; with as_is=true the files go in as they are, each its own digest (recorded after the floor block, the bytes themselves not dated), the user's choice and never a size's; a file of any size is streamed; and the tree's 84-byte root document is committed under the same position. The committed bytes could not have been finished before the floor block and were committed no later than the commit; a file recorded as is existed by the commit, and nothing bounds it from below. The committed bytes are virtual: the original plus the proof rebuilds them. The proof commits only the tree's root, so every call writes the BitGraph's export (bitgraph-export/1) beside what was recorded: with a file, it shows that file is in the BitGraph, with nothing of BitGraph's required. Keep it.

BitGraph gives bytes a causal position in a forward-only ledger. Base serves as a public clock: when a position opens, the enclave binds the newest Base block into it, from a header it hashes and checks itself, and a block's hash exists only once the block does, so every position is pinned to a public timeline. Nothing is written to a chain for the floor; seconds after the commit, a Merkle root over new proofs' hashes is written to Base as the ceiling in time. Proofs made before the switch stand on an Ethereum anchor instead and verify as before. This server reads files locally; only digests, the tree's root document, position records and each file's sealed recovery entry ever leave the machine. A recovery entry is stored under a name derived from the file's hash and encrypted with a key derived from it too, so anyone who knows the file's SHA-256 (holding the file, or a published digest) can find and open it, and nobody else; it is how a file finds its proof again when the export is lost (recovery=false keeps none). File contents are never uploaded, and files are never modified.

```sh
claude mcp add bitgraph -- npx -y @mikeargento/bitgraph-mcp
```

Tools:

- `bitgraph_record` makes a BitGraph of files and folders: one tree, one position, every file a leaf. A directory is every regular file under it, recursively, with hidden entries and symbolic links left out. Files already on record come back as `on record` with their earliest position instead of being made again: a file in an earlier tree is found through its sealed recovery entry and verified from its own bytes; so is the original of an earlier fused file or a member of an earlier set. Unknown is not new: a file whose entries could not all be read is refused with the reason. Pass `again: true` to make a new BitGraph regardless. Each file comes back with its leaf (one of N), the tree with its position and proof page, and the export with its path. `export_dir` (default: the folder that holds the first path given, so a folder's export sits beside it, never inside it) and `exports` (`owner`, the default: one file listing every leaf and its name; `members`: one export per file; `both`; `none`) choose what is written, with SPEC.md, the exact text the proof pins, beside it when the site serves that text. A BitGraphed file (one that carries its own proof) is never minted: its proof is judged offline and reported. BitGraphs are permanent.
- `bitgraph_check` reports whether files, folders or digests are on record (`on_record`: a recording of the exact bytes, a leaf of a tree found through its recovery entry, the original of an earlier fused file, or a member of an earlier set), with every position each one occupies. A BitGraphed file is judged offline from the proof inside, and its window is stated. Read-only.
- `bitgraph_get_proof` fetches a proof by digest, BitGraph number, or file path, with every position the same bytes occupy and the window: after the floor block's time, and by the Base ceiling block's time once it exists. An earlier, Ethereum-floored proof also states its closing anchor, a bound in position, never a clock time. Read-only.
- `bitgraph_open` holds a position BEFORE a task starts and returns its commitment string, its floor block and a token. Put the commitment inside the task (the prompt, a comment, a field), then call `bitgraph_commit` within 120 seconds.
- `bitgraph_commit` seals the task bytes under that position: the file is read here, the commitment is looked for inside it before anything is sent, only the digest travels, and the proof is written beside the file. The task could not have existed before the floor block; outputs recorded afterwards with `bitgraph_record` sit after it.

Configuration is by environment variable. `BITGRAPH_API_URL` overrides the endpoint (default `https://bitgraph.ing`). `BITGRAPH_API_KEY`, when set, is sent as a Bearer token on recordings. A client that passes a progress token gets progress notifications through the scan and the tree's phases.

Proofs are the bitgraph/1 schema and exports are bitgraph-export/1; both verify offline, without this server or any service, using `@mikeargento/bitgraph-verify`: `verifyExport` checks an export with the file it is about, one claim per line (the proof and its attestation, the spec pin, the root, the file's leaf, the floor, and the Base ceiling and Ethereum settlement once `npx -p @mikeargento/bitgraph-sdk bitgraph export complete <export>` has added them). The spec the proof pins is SPEC.md version 1, frozen 2026-10-04, SHA-256 `QazdIR0JYtHQwQuIISo7bvH1gxUvTS2cY+tW6BjUIRs=`. An export holds no copy of any file. A BitGraphed file (carrier/2) stays the single-file form that carries its own proof. This server is a thin shell over `@mikeargento/bitgraph-sdk`, the same engine as the `bitgraph` CLI; the tree pipeline underneath is `@mikeargento/bitgraph`, the licensed package; this client is MIT.

BitGraph itself lives at [bitgraph.ing](https://bitgraph.ing). The protocol, this package's source, and the rest of the documentation are in the main repository: [github.com/mikeargento/bitgraph](https://github.com/mikeargento/bitgraph).
