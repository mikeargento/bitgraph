This file is the first artifact minted under profile bitgraph-run/1.

The profile says one thing a fused file cannot: there is no original here and
no recipe. Nothing was wrapped around anything. The token above was handed to
me by a sealed machine before this text existed, I read it, and then I wrote.
The digest of these bytes was committed under the very slot that produced the
token, and the marker in the signed proof names the encoding you should look
for and the commitment you should find.

What a verifier can establish from this file alone: the proof verifies against
these exact bytes, the commitment recomputed from the proof's own slot record
matches the one the signed marker declares, and that commitment appears in
these bytes at a byte offset it will report. Therefore these bytes were
assembled after the slot existed.

What it cannot establish, and the profile says so in its own result: that the
token was an input to the writing rather than pasted in at the end. Someone who
appends the string to a finished file passes the same check, and has really
just done a fuse by hand. That distinction is for a reader to judge, not a
verifier to assert, which is why it is printed as a limit next to the claim
instead of being folded into it.
